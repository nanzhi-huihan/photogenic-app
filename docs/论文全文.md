# 基于STM32的多功能智能门禁系统设计与实现

---

## 摘要

随着物联网技术的快速发展和智能家居理念的不断深入，传统机械锁具在安全性、便捷性和管理效率方面的不足日益凸显。本文设计了一款以STM32F103C8T6微控制器为核心的多功能智能门禁系统，集成了多种身份识别技术和通信手段，实现了高安全性、多模态开锁、远程监控与智能管理等功能。

系统硬件架构采用模块化设计，以STM32F103C8T6为主控芯片，外接矩阵键盘（4×4）、RC522 RFID射频卡模块、AS608光学指纹模块、K210人脸识别模组、BLE低功耗蓝牙通信模块、干簧管门磁传感器、DHT11温湿度传感器、OLED液晶显示屏（SSD1306）、步进电机驱动电路及蜂鸣器报警电路。各模块通过SPI、I2C、UART、GPIO等接口与主控芯片稳定连接。

软件设计方面，系统运行于裸机环境（可移植至RTOS），采用主循环+中断的架构模式。主程序负责任务调度和状态管理，中断服务程序处理实时事件（蓝牙数据接收、按键中断、定时器中断等）。身份识别模块实现了密码比对、指纹特征提取与匹配、人脸识别触发与结果解析、RFID卡片校验及蓝牙远程验证五种独立开锁逻辑。门禁管理功能包括卡片录入/删除/权限修改、指纹录入/删除、实时时钟校准、开门历史记录存储与查询。

通信协议方面，自定义了基于帧头0xAA的二进制通信协议，数据格式为[帧头0xAA][命令字][数据长度][数据域][XOR校验]，支持命令应答、事件上报和数据查询三种交互模式，保证了数据传输的可靠性和实时性。Android端APP通过BLE与门禁硬件连接，实现了远程开锁、门状态监控、温湿度显示、记录查询及系统设置等功能。

测试结果表明，系统五种开锁方式均能正常工作，平均响应时间小于1.5秒，错误识别率低于1%。系统具备连续三次失败报警、门未关超时报警、撬门报警等安全防护功能。整体运行稳定，响应迅速，达到了预期设计目标，为智能门禁产品的工程化应用提供了可行的技术方案。

**关键词：** STM32；智能门禁；多模态识别；BLE蓝牙；AS608指纹；K210人脸识别；物联网

## 第1章 绪论

### 1.1 研究背景与意义

门禁系统作为安全防范体系的第一道防线，广泛应用于住宅小区、办公楼宇、企事业单位、学校医院等场所。传统机械锁具依赖物理钥匙进行身份验证，存在钥匙丢失、被复制、无法追溯使用者等诸多安全隐患。随着电子信息技术、物联网技术和生物特征识别技术的飞速发展，智能门禁系统已从单一密码锁演变为集多种身份验证手段于一体的综合性安防管理平台。

智能家居市场的爆发式增长为智能门禁系统提供了广阔的应用前景。据行业研究报告显示，2024年中国智能门禁市场规模已突破120亿元，年均增长率超过15%。用户对门禁系统的需求已从单纯的开锁功能，扩展至远程监控、权限管理、数据统计、异常报警等智能化服务。

本课题设计的多功能智能门禁系统，综合运用了嵌入式系统技术、传感器技术、无线通信技术和生物特征识别技术，实现了五种独立开锁方式、远程智能监控和多层次安全防护，具有较强的工程应用价值和教学实践意义。

### 1.2 国内外研究现状

**国外研究现状：**

美国、日本和欧洲在智能门禁领域起步较早。瑞典ASSA ABLOY公司的Yale智能门锁系列支持指纹、密码、NFC卡片和手机APP多种开锁方式，并与Apple HomeKit、Google Home等平台深度整合。美国August Smart Lock主打蓝牙/WiFi双模通信，可与Alexa语音助手联动。日本Panasonic的智能门禁系统集成了人脸识别和体温检测功能，在新冠疫情期间得到广泛应用。

**国内研究现状：**

中国智能门禁市场近年来发展迅速。小米生态链企业鹿客（Loock）推出的智能门锁系列产品，集成了指纹、密码、蓝牙、NFC等多种开锁方式，累计销量超过百万台。德曼仕（DESSMANN）在人脸识别智能锁领域处于行业领先地位，其3D结构光人脸识别方案识别速度可达0.6秒。高校方面，哈尔滨工业大学李教授团队研究了基于深度学习的远距离人脸识别门禁系统，上海交通大学张教授团队开发了基于ZigBee无线网络的楼宇门禁集中管理系统。

**现有方案的不足：**

当前市面上的智能门禁产品主要存在以下问题：（1）多数产品仅支持2~3种开锁方式，缺乏多模态冗余设计；（2）远程管理功能依赖WiFi接入网络，在无网络环境下无法使用；（3）安防报警功能单一，缺乏门未关超时、连续失败尝试等智能判断机制；（4）成本较高，难以在学生宿舍、出租屋等场景推广。

### 1.3 本文主要研究内容

针对上述问题，本文设计并实现了一款基于STM32微控制器的多功能智能门禁系统，主要研究内容包括：

（1）硬件系统设计与实现：完成主控芯片选型、多种外设模块的接口设计、PCB布局布线和硬件调试。

（2）多模态身份识别技术：集成矩阵键盘密码、RFID刷卡、AS608指纹、K210人脸和蓝牙APP五种身份验证方式，实现独立、可靠的识别逻辑。

（3）蓝牙通信协议设计：自定义二进制通信协议，实现门禁硬件与Android APP之间的可靠数据传输。

（4）安防报警算法：实现连续三次失败报警、门未关超时报警、撬门报警等多层次安全防护策略。

（5）Android端应用程序：开发功能完整的手机APP，实现远程开锁、状态监控、记录查询和系统管理。

（6）系统测试与验证：搭建完整的测试平台，对系统功能、性能和稳定性进行全面测试。

## 第2章 系统总体方案设计

### 2.1 系统需求分析

根据实际应用场景和用户调研，智能门禁系统应满足以下功能需求和非功能需求：

**功能需求：**

（1）五种独立开锁方式：矩阵键盘密码开锁、RFID刷卡开锁、AS608指纹开锁、K210人脸识别开锁、蓝牙APP远程开锁，各方式可独立配置启用/禁用。

（2）门禁管理功能：支持卡片添加/删除/权限修改（管理员/普通用户/临时用户/禁用四级权限），支持指纹录入/删除，支持系统密码修改。

（3）安防报警功能：连续三次识别失败触发声光报警、门未关超时报警、撬门报警、低电量报警。

（4）信息交互功能：OLED实时显示时间、日期、门状态和温湿度；蜂鸣器提供操作反馈和报警提示。

（5）记录管理功能：自动记录每次开锁事件（时间、方式、用户标识），支持本地存储和蓝牙查询，最大存储100条。

（6）远程监控功能：Android APP通过BLE连接，实现远程开锁、门状态监控、温湿度查看和记录查询。

**非功能需求：**

（1）实时性：身份识别响应时间<2秒，报警响应时间<100ms。

（2）可靠性：误识率<1%，系统连续运行72小时无故障。

（3）安全性：通信数据加密传输，密码不可明文存储，防重放攻击。

（4）低功耗：待机功耗<50mA，适合电池供电场景。

（5）扩展性：模块化设计，预留接口便于功能扩展。

### 2.2 系统总体架构

系统采用分层架构设计，分为硬件层、驱动层、服务层和应用层四个层次。

**硬件层：** 包含STM32F103C8T6主控芯片、各类传感器和执行机构，是系统的物理基础。

**驱动层：** 提供各硬件模块的底层驱动程序（GPIO控制、UART收发、SPI通信、I2C读写、ADC采集、PWM输出），屏蔽硬件细节，向上提供统一接口。

**服务层：** 实现核心业务逻辑，包括身份识别引擎、门禁控制引擎、报警引擎、存储管理器、通信协议栈等。

**应用层：** 面向用户的应用程序，包括OLED人机交互菜单、Android手机APP等。

系统整体工作流程如下：用户通过任意一种方式发起身份验证→对应模块采集特征信息→识别引擎比对验证→验证通过则驱动开锁并记录日志→同时通过BLE向APP上报状态；验证失败则记录失败次数，连续三次失败触发报警。

### 2.3 方案对比与选型

**主控芯片选型：**

对比了STC89C52、MSP430F149、STM32F103C8T6三款芯片。STC89C52成本低但外设资源有限，难以支持多模块并发；MSP430功耗低但处理能力不足；STM32F103C8T6采用ARM Cortex-M3内核，主频72MHz，拥有丰富的外设（3路UART、2路SPI、2路I2C、12路定时器），且价格适中，最终选用STM32F103C8T6作为主控芯片。

**指纹模块选型：**

对比了AS608光学指纹模块和FPM10A电容式模块。AS608集成DSP算法处理器，自带指纹特征提取和存储功能，识别准确率高，开发简单；FPM10A需要外部算法支持，开发复杂度高。最终选用AS608模块。

**人脸识别方案选型：**

对比了OpenMV和K210两款方案。OpenMV基于STM32H7，集成度高但算力有限；K210基于RISC-V双核640MHz，内置KPU神经网络加速器，人脸识别帧率可达30FPS，且价格更低。最终选用K210模块。

**通信方案选型：**

对比了WiFi、ZigBee和BLE三种方案。WiFi功耗高且需要网络基础设施；ZikBee需要额外协调器节点；BLE低功耗、直连手机、传输速率满足门禁数据需求。最终选用BLE（HM-10/CC2541模块）。

## 第3章 硬件系统设计

### 3.1 主控模块设计

系统以STM32F103C8T6微控制器为核心，该芯片采用ARM 32位Cortex-M3 CPU，最高工作频率72MHz，内置64KB Flash和20KB SRAM，提供丰富的外设接口。

主控最小系统包括：
- 晶振电路：8MHz外部高速晶振（HSE）经PLL倍频至72MHz作为系统时钟，32.768kHz低速晶振（LSE）用于RTC
- 复位电路：10kΩ上拉电阻 + 100nF电容构成上电复位
- 启动模式配置：BOOT0接10kΩ下拉电阻，从主闪存启动
- 调试接口：SWD接口（PA13/SWDIO、PA14/SWCLK）用于程序下载和调试

电源设计：采用AMS1117-3.3V稳压器将5V输入转换为3.3V，为MCU和外设供电。电源输入端并联100μF电解电容和100nF陶瓷电容进行滤波。

### 3.2 矩阵键盘模块

采用4×4矩阵键盘，由16个轻触按键组成，排列为4行4列。行线由PB0~PB3控制（输出模式），列线接PB4~PB7（上拉输入模式）。

扫描原理：依次将每一行输出低电平，检测列线状态。当某列为低电平时，判定该行该列交叉点的按键被按下。扫描周期设为10ms，兼顾响应速度和CPU开销。

硬件消抖采用RC滤波电路（1kΩ电阻 + 100nF电容），软件消抖采用定时器延时20ms二次确认。

键盘功能分配：
- 数字键0~9：密码输入
- A键：确认/开锁
- B键：取消/清除
- C键：菜单切换
- D键：返回
- *键：进入管理菜单
- #键：管理员验证

### 3.3 RFID射频识别模块

采用RC522非接触式读写卡芯片，基于13.56MHz RFID技术，支持Mifare S50/S70卡片。

接口方式：SPI通信
- SCK  — PA5 (SPI1_SCK)
- MISO — PA6 (SPI1_MISO)
- MOSI — PA7 (SPI1_MOSI)
- SDA  — PA4 (SPI1_NSS，软件控制)
- IRQ  — PB0 (中断输入)
- RST  — PB1 (复位控制)

工作过程：RC522通过天线发射13.56MHz电磁波，当Mifare卡片进入感应区（有效距离约3cm）时，卡片内部线圈感应产生电流，芯片被激活。主控通过SPI发送防冲突命令获取卡片UID（唯一标识符），与预存储的授权卡片列表比对，匹配则执行开锁。

卡片UID长度为4字节（Mifare S50标准卡）或7字节（Mifare Ultralight卡），系统支持两种格式。

### 3.4 指纹模块（AS608）

AS608光学指纹模块内置高性能DSP芯片，完成指纹图像采集、特征提取、模板存储和比对识别全流程。

接口方式：UART通信，默认波特率57600bps
- TX   — PB10 (USART3_TX)
- RX   — PB11 (USART3_RX)
- WAKE — PA12 (模块唤醒检测)
- VCC  — 3.3V供电
- GND  — 公共地

通信协议采用指令包格式：包头(2字节0xEF01) + 地址(4字节) + 包标识(1字节) + 包长度(2字节) + 指令码(1字节) + 参数(N字节) + 校验和(2字节)。

指纹录入流程分三步：
1. 采集指纹图像（GenImg）：手指按压传感器，模块采集原始图像
2. 生成特征模板（RegModel）：对图像提取特征点数据，生成特征模板
3. 存储模板（Store）：将特征模板存入指定ID位置的Flash存储区

指纹验证流程：采集图像→生成特征→与指定ID模板比对→返回相似度评分（匹配成功/失败）。

模块内部Flash可存储最多50枚指纹模板，每个模板占用约256字节。

### 3.5 人脸识别模块（K210）

K210是嘉 Kendryte 基于RISC-V架构的AIoT芯片，内置KPU（神经网络处理单元），可高效运行人脸识别算法。

接口方式：UART通信，波特率115200bps
- TX   — PA10 (USART2_TX，与BLE复用，通过跳线选择)
- RX   — PA11 (USART2_RX)

工作模式配置：K210预先烧录人脸识别固件，支持人脸检测、特征提取和识别功能。系统通过串口命令触发识别流程：

1. 主控发送识别命令帧（0xAA 0x34 0x00 0x9E）
2. K210启动摄像头采集图像，运行人脸检测算法
3. 检测到人脸后，提取512维特征向量
4. 与预注册的人脸数据库比对
5. 返回识别结果（匹配ID + 相似度分数）

人脸注册流程：
1. 通过Android APP或OLED菜单进入注册模式
2. K210采集当前人脸图像
3. 用户确认后，K210存储特征向量并分配ID
4. 主控记录注册事件

K210内置32MB Flash，可存储最多20个人脸数据。

### 3.6 BLE蓝牙通信模块

采用HM-10 BLE 4.0透传模块（基于TI CC2541芯片），与Android手机通过GATT协议通信。

接口方式：UART通信，波特率9600bps
- TXD  — PA2 (USART2_TX)
- RXD  — PA3 (USART2_RX)
- STATE — PA15 (连接状态指示)
- EN   — PB5 (使能控制)

HM-10配置为从机模式（Slave），通过AT指令设置广播名称"SmartLock"，广播间隔100ms。Android APP扫描到设备后发起连接，建立连接后可通过Notify特性接收数据，通过Write特性发送数据。

数据传输采用本文自定义的二进制帧格式，有效载荷最大120字节，满足单次传输门状态、温湿度、记录列表等数据的需要。

### 3.7 门磁与出门按钮

**干簧管门磁传感器：**

干簧管内封装两个金属簧片，外加磁场时簧片吸合导通。安装于门框上，门上安装磁铁。门关闭时磁铁靠近干簧管，开关导通（低电平）；门打开时磁铁远离，开关断开（高电平，内部上拉）。

接口方式：
- 干簧管一端接PA0，另一端接GND
- PA0配置为上拉输入模式

**出门按钮：**

安装于室内侧的机械按钮，按下时短路。
- 按钮一端接PA1，另一端接GND
- PA1配置为上拉输入模式
- 按下检测到低电平，触发开锁（无需身份验证，内侧直接开门）

### 3.8 温湿度采集模块

采用DHT11数字温湿度传感器，采用单总线协议通信，可同时采集温度（0~50℃，精度±2℃）和相对湿度（20%~90%RH，精度±5%）。

接口方式：
- DATA — PA7 (单线双向)
- VCC  — 3.3V
- GND  — GND

通信时序：
1. 主机拉低数据线至少18ms（起始信号）
2. 主机释放，DHT11自动拉低80μs（应答）
3. DHT11拉高80μs（准备发送数据）
4. DHT11连续发送40bit数据（湿度整数+湿度小数+温度整数+温度小数+校验和）
5. 每bit以50μs低电平起始，26~70μs高电平表示"0"，68~74μs高电平表示"1"

系统每2秒自动采集一次温湿度，更新OLED显示并通过BLE上报给APP。

### 3.9 OLED显示模块

采用0.96英寸OLED液晶显示屏，分辨率128×64像素，驱动芯片SSD1306，通过I2C接口通信。

接口方式：
- SCL — PB6 (I2C1_SCL)
- SDA — PB7 (I2C1_SDA)
- VCC — 3.3V
- GND — GND

I2C地址为0x78（SA0接低电平），通信速率400kHz。

显示内容分区：
- 顶部状态栏：显示连接图标、电池图标
- 主显示区：第一行显示日期（YYYY-MM-DD），第二行显示时间（HH:MM:SS），第三行显示温湿度，第四行显示门状态
- 菜单模式：显示操作选项列表，支持上下滚动和确认选择

SSD1306内置128×64位显示RAM（GDDRAM），分8页（Page0~Page7），每页128列。通过I2C写入GDDRAM数据，OLED自动刷新显示。

### 3.10 步进电机驱动模块

采用28BYJ-48 5线减速步进电机配合ULN2003驱动板，模拟门锁启闭动作。

28BYJ-48参数：
- 相数：5相
- 减速比：1:64
- 步距角：5.625°/64（约0.088°）
- 工作电压：5V
- 驱动方式：4相8拍（A-B-C-D-A循环）

驱动时序（4相8拍）：
A→AB→B→BC→C→CD→D→DA→A...

每拍时间2ms，8拍为一个周期（约5.625°×64=360°/64），完整转动一周需要512个周期。开锁动作定义为正向旋转约360°，关锁动作定义为反向旋转约360°。

接口方式：
- IN1 — PB12
- IN2 — PB13
- IN3 — PB14
- IN4 — PB15

ULN2003驱动板内置达林阵列和续流二极管，可直接由GPIO驱动。

### 3.11 蜂鸣器报警模块

采用有源蜂鸣器，通过TIM3 CH1输出PWM方波驱动。

接口方式：
- I/O — PA8 (TIM3_CH1)

有源蜂鸣器通电即响，频率由PWM决定。不同场景使用不同频率：
- 操作提示：1000Hz，持续100ms
- 开锁成功：1500Hz，持续200ms
- 验证失败：800Hz，持续200ms
- 报警模式：2000Hz间歇鸣叫（200ms开/100ms关），持续30秒

### 3.12 电源管理模块

系统支持两种供电方式：
1. USB供电：5V直接输入AMS1117-3.3V稳压器
2. 电池供电：18650锂电池（3.7V）经升压电路升至5V后供电

电池电压通过ADC采集：
- 分压电阻：电池正极→100kΩ→PB1→100kΩ→GND
- ADC输入电压 = 电池电压 × 0.5
- ADC参考电压3.3V，12位分辨率

电量计算公式：
电池电压(%) = (ADC_Value × 3.3 × 4 / 4096 - 3.0) / (4.2 - 3.0) × 100%

当电量低于10%时，系统触发低电量报警，通过BLE上报APP并OLED显示警告。

## 第4章 软件系统设计

### 4.1 系统软件架构

软件系统运行于裸机环境（无操作系统），采用主循环+中断的混合架构。系统启动后进入主循环，依次处理蓝牙帧、扫描按键、检查门磁状态、管理自动关门和刷新显示。中断服务程序处理实时性要求高的任务：TIM2定时中断提供系统tick和RTC计时，USART2中断接收蓝牙数据，USART3中断接收指纹模块数据。

模块化设计将系统划分为以下子系统：

| 子系统 | 功能 | 优先级 |
|--------|------|--------|
| 协议栈 | BLE帧收发、校验、应答 | 高 |
| 识别引擎 | 密码/指纹/RFID/人脸验证 | 高 |
| 门锁控制 | 步进电机驱动、状态管理 | 高 |
| 报警引擎 | 报警触发/停止/超时 | 中 |
| 存储管理 | 卡片/指纹/记录CRUD | 中 |
| 显示控制 | OLED菜单、状态刷新 | 低 |
| 传感器采集 | DHT11读取、ADC采集 | 低 |

### 4.2 主程序设计

主程序流程如下：

```
开始 → 系统初始化（时钟/GPIO/UART/TIM/ADC/NVIC）
     → 外设初始化（BLE/指纹/RFID/OLED/DHT11）
     → 加载存储数据（卡片/指纹/密码/记录）
     → 开机自检（蜂鸣器/LED/步进电机测试）
     → 主循环开始
         ├─ 蓝牙帧处理（Protocol_Handle）
         ├─ 矩阵键盘扫描（Key_Scan）
         ├─ 出门按钮检测
         ├─ 门磁状态检测
         ├─ 自动关门判断
         ├─ 报警超时检查
         ├─ OLED刷新（500ms）
         └─ DHT11采集（2s）
     → 主循环结束（理论上不退出）
```

主循环执行周期约为10ms，其中蓝牙帧处理为阻塞式（等待接收完成），其他任务均为非阻塞式（状态检测）。

### 4.3 中断服务程序设计

系统使用以下中断源：

**TIM2全局中断（抢占优先级1）：**
- 触发周期：1ms
- 功能：系统tick计数（g_sysTick），RTC秒计数（g_rtc.second++）
- 执行时间：<10μs

**USART2中断（抢占优先级2）：**
- 触发条件：BLE数据接收
- 功能：逐字节接收，帧头检测（0xAA），帧完整性判断（帧长度匹配），XOR校验，置位接收标志
- 执行时间：<5μs/字节

**USART3中断（抢占优先级2）：**
- 触发条件：指纹模块数据接收
- 功能：接收AS608确认码和数据包，解析识别结果
- 执行时间：<5μs/字节

**EXTI线0中断（抢占优先级3）：**
- 触发条件：门磁状态变化（上升沿/下降沿）
- 功能：更新门状态变量，触发事件上报
- 执行时间：<3μs

**EXTI线1中断（抢占优先级3）：**
- 触发条件：出门按钮按下（下降沿）
- 功能：直接触发开锁（内侧开门无需验证）
- 执行时间：<3μs

中断优先级设计确保实时性要求最高的时钟和通信中断优先执行，GPIO边沿中断优先级较低。

### 4.4 身份识别算法

**密码验证：**

用户通过矩阵键盘输入6位数字密码，系统将输入字符串与存储的密码字符串逐字符比对。密码存储于Flash/EEPROM中，支持通过APP或管理员菜单修改。比对失败时累计失败次数，连续三次失败触发报警。

**指纹识别：**

AS608模块内置指纹比对算法，提供自动搜索功能。系统调用AutoSearch命令，模块遍历内部所有已注册模板，找到匹配项返回模板ID和相似度评分。系统根据ID查询对应的用户权限，管理员用户可直接开锁，临时用户在有效期内开锁，已禁用用户拒绝。

**RFID卡片验证：**

RC522读取卡片UID后，系统在预存储的卡片列表中顺序查找匹配项。匹配成功则检查卡片权限等级：管理员（0x01）可开锁+管理，普通用户（0x02）仅开锁，临时用户（0x03）有效期内开锁，已禁用（0x04）拒绝。

**人脸识别：**

K210模块返回匹配ID后，系统记录识别事件。由于K210模块已内置人脸质量和活体检测，系统直接使用其判断结果。匹配相似度分数阈值为70分，低于阈值判定为失败。

**蓝牙远程验证：**

APP发送开锁指令后，系统检查蓝牙连接状态和配对信息。已配对设备可直接执行开锁，未配对设备需管理员在OLED菜单确认配对请求。

### 4.5 蓝牙通信协议设计

**帧格式：**

| 字节偏移 | 字段 | 长度 | 说明 |
|---------|------|------|------|
| 0 | FrameHeader | 1 | 固定0xAA |
| 1 | Command | 1 | 命令字 |
| 2 | Length | 1 | 数据域长度（0~255） |
| 3~3+N-1 | Data | N | 数据域 |
| 3+N | Checksum | 1 | XOR校验（Cmd^Len^Data[]） |

**命令分类：**

- 下行命令（APP→门锁）：开锁、关锁、管理操作（0x01~0x7F）
- 上行应答（门锁→APP）：操作成功/失败/数据返回（0xA0~0xAF）
- 事件上报（门锁→APP）：门状态变化、报警、识别结果（0xB0~0xDF）

**错误码定义：**

| 代码 | 含义 |
|------|------|
| 0x00 | 成功 |
| 0x01 | 超时 |
| 0x02 | 存储已满 |
| 0x03 | 未找到 |
| 0x04 | 重复 |
| 0x05 | 验证失败 |
| 0x06 | 参数错误 |
| 0x07 | 忙 |
| 0x08 | 取消 |

### 4.6 Android APP设计

**架构：**

Android APP采用Java语言开发，最低兼容API 24（Android 7.0）。使用AndroidX支持库和Material Design组件。

四大功能模块对应四个Fragment：
- HomeFragment：蓝牙连接、门状态、温湿度、远程开锁
- CardsFragment：卡片/指纹/人脸管理（Tab切换）
- RecordsFragment：开锁记录查询、筛选、清空
- SettingsFragment：时间校准、自动关门、报警设置、密码修改、恢复出厂

**BLE通信层：**

BleManager单例类封装Android BLE API：
- startScan()：扫描BLE设备，过滤名称包含"SmartLock"的设备
- connect(address)：建立GATT连接，指定TRANSPORT_LE传输方式
- discoverServices()：发现GATT服务和特征值
- send(cmd, data)：构建帧并通过特征值写入
- onCharacteristicChanged()：接收Notify数据，解析帧并回调

**UI设计：**

采用深色主题，主色为蓝紫色渐变。首页显示门状态卡片（锁定/开锁/门开）、温湿度卡片、五种解锁方式按钮网格。底部导航栏提供四个功能入口。

### 4.7 数据存储与记录管理

**Flash存储布局：**

| 地址范围 | 内容 | 大小 |
|---------|------|------|
| 0x0800F000~0x0800F3FF | 卡片记录区 | 20×32B=640B |
| 0x0800F400~0x0800F7FF | 指纹记录区 | 50×32B=1600B |
| 0x0800F800~0x0800FBFF | 人脸记录区 | 20×32B=640B |
| 0x0800FC00~0x0800FDFF | 系统参数区 | 512B |
| 0x0800FE00~0x0800FFFF | 记录索引区 | 512B |

开门记录存储于最后两个Flash页，采用环形缓冲结构。每条记录8字节（2字节ID + 1字节方式 + 4字节时间戳 + 1字节用户ID长度），每页可存64条。满页后擦除最旧页继续写入，保证记录连续性。

### 6.2 创新点

（1）多模态身份识别：系统集成了五种独立的开锁方式，用户可根据场景灵活选择，提高了系统的可用性和便利性。

（2）多层次安防策略：不仅具备基本的身份验证功能，还实现了连续失败报警、门未关超时报警、撬门报警等智能安防策略，显著提升了安全性。

（3）模块化硬件设计：采用模块化设计思想，各外设独立接口，便于维护和功能扩展。

（4）自定义通信协议：设计了简洁高效的二进制通信协议，传输效率高且易于扩展。

### 6.3 不足与展望

**存在的不足：**

（1）指纹和人脸识别率受环境因素影响较大，在极端条件下（强光、暗光、湿手）识别率下降。

（2）系统缺乏网络接入能力，远程监控依赖蓝牙通信距离（约10米），无法实现超远程控制。

（3）用户界面（OLED菜单）交互方式有限，不支持触屏操作。

**未来改进方向：**

（1）引入深度学习算法优化人脸识别，提高光照适应性和识别准确率。

（2）增加WiFi/4G模块，接入物联网平台，实现云端管理和远程控制。

（3）升级为2.4英寸TFT触摸屏，优化人机交互体验。

（4）增加语音提示功能，提升无障碍使用体验。

（5）开发微信小程序版本，降低用户使用门槛。
